# 基于 MongoDB 的问卷系统——第一阶段设计草案

> 依据《大作业一.pdf》的初始需求整理，作为第一阶段编码前的设计基线。  
> 设计目标是：功能满足需求、MongoDB 建模合理、跳转与校验数据化、便于第二阶段扩展。

## 1. 范围与目标

第一阶段交付一个可运行的简化在线问卷系统，支持：

- 用户注册、登录，只能看到自己创建的问卷；
- 创建、发布、关闭问卷，设置截止时间；
- 单选、多选、文本填空、数字填空四类题目；
- 题目必答、选项数量、文本长度、数字范围等校验；
- 基于单选、多选、数字填空结果的可配置跳转；
- 所有业务操作必须登录，通过链接进入后填写、提交，每次填写独立保存；
- 填写页为单页扁平布局，所有题目在同一页面滚动浏览；
- 创建者查看整卷和单题统计。

第一阶段不追求复杂界面，也不做题目库复用、团队协作、数据导出、图表美化、问卷版本对比等功能。

## 2. 角色与用例

| 角色 | 主要用例 |
|---|---|
| 未登录访客 | 注册、登录；打开问卷链接时被引导登录 |
| 登录用户 | 创建问卷、管理自己的问卷、填写他人问卷 |
| 问卷创建者 | 编辑草稿、发布、关闭、设置截止时间、查看统计和答卷 |

核心用例：

1. 注册 / 登录 / 查看当前用户；
2. 创建问卷草稿；
3. 添加、修改、删除、排序题目；
4. 配置题目校验与跳转规则；
5. 发布问卷并生成分享链接；
6. 填写者在单页中作答，系统按规则显示/隐藏题目并滚动到目标题；
7. 服务端校验后保存答卷；
8. 创建者查看整卷或单题统计；
9. 关闭问卷或到期后拒绝新答卷。

## 3. 需求拆解与关键取舍

### 3.1 登录与匿名（已确认）

系统除注册、登录外的所有业务操作都必须登录，包括创建问卷、编辑题目、发布、关闭、打开问卷链接、填写、提交和查看统计。

- 未登录访问 `/survey/{slug}` 时跳转登录页，登录成功后回到该问卷；
- 后端所有业务接口都校验登录状态，未登录返回 401；
- `allowAnonymous` 是**问卷发布者在问卷上设置的选项**，不是免登录开关；
- `allowAnonymous = true` 表示答卷不记录 `respondentId`，创建者无法把某份答卷与具体用户关联；
- `allowAnonymous = false` 时，答卷记录 `respondentId`。

匿名的验收标准是**问卷创建者看不到填写者身份**，不要求数据库层面绝对不可关联。系统内部可以保留 HMAC `dedupeKey` 用于防重复，但该字段不通过任何接口返回。匿名只影响“答卷是否与用户身份关联”，不影响填写权限。

### 3.2 重复填写

问卷增加 `allowMultipleResponses`：

- `false`：同一登录用户对同一问卷只能提交一次；
- `true`：允许同一用户多次提交，每次生成一条独立答卷。

因为填写必须登录，所以即使问卷设置为匿名，服务端仍然知道当前用户是谁。非匿名情况下，用 `dedupeKey = surveyId + ":" + respondentId` 加唯一索引，防止“先查再插”的并发重复。匿名情况下，若 `allowMultipleResponses = false`，使用服务端密钥对 `surveyId + ":" + userId` 做 HMAC 后作为 `dedupeKey`，只用于唯一索引查重，不保存 `respondentId`。`dedupeKey` 属于内部字段，任何接口都不返回。

另外，每次进入填写页时前端生成一个 `submissionId`（UUID），随提交请求一起发送。同一填写页的重复点击、网络重试复用同一个 `submissionId`；服务端用 `{surveyId, submissionId}` 唯一索引保证只插入一次。重复请求返回已存在的 `responseId`，不会新建答卷。这样即使问卷允许重复提交，也能避免一次填写被误保存成多条。

### 3.3 发布后题目结构冻结（已确认）

问卷状态分为：

- `draft`：可任意编辑；
- `published`：**题目、选项、题目校验规则、跳转规则一律不可修改**；标题、说明、截止时间仍可修改；`allowAnonymous` 和 `allowMultipleResponses` 也冻结，避免历史答卷的语义变化；
- `closed`：只读，不再接收答卷；第一阶段关闭是终态，不提供“重新开放”。

状态流转只允许 `draft → published → closed`，不允许从 `closed` 回到 `published`。原因是答卷只保存 `questionId` / `optionId`，发布后如果改题或删选项，历史统计会错位。第一阶段用“发布后题目结构冻结”保证统计一致性；第二阶段若确实要改结构，再通过 `version` 或新建问卷版本实现迁移。

### 3.4 跳转方向与多选匹配（已确认）

第一阶段只允许跳转目标为**当前题之后的题目或结束**（即向问卷末尾方向跳），避免出现环。运行时仍保留 `visited` 集合和最大步数保护。后续如需跳回前面的题，只需放宽发布校验，规则结构不用改。

多选跳转采用**集合精确匹配**：用户选中的选项集合必须与规则配置的集合完全一致，顺序无关，多一个或少一个都不触发。例如规则配置为 `[苹果, 葡萄]`：

- 用户选中 `[苹果, 葡萄]`：触发；
- 用户选中 `[葡萄, 苹果]`：触发（顺序无关）；
- 用户选中 `[苹果, 香蕉, 葡萄]`：不触发（多了一个）；
- 用户只选 `[苹果]`：不触发（少了一个）。

第一阶段多选只实现 `setEq` 这一种跳转运算符；“包含某选项”“按选中数量”等语义不进入界面，后续确有需要再作为新运算符扩展。

### 3.5 题型划分

文档要求至少三种题型。这里实现四种 `type`：

| type | 含义 | 是否有选项 |
|---|---|---|
| `single` | 单选 | 是 |
| `multiple` | 多选 | 是 |
| `text` | 文本填空 | 否 |
| `number` | 数字填空 | 否 |

把“填空”拆成 `text` 和 `number`，可以让校验和统计逻辑更直接，避免在一个题型里再嵌套 `valueType` 分支。

### 3.6 扁平化填写页（已确认）

填写页不使用“一题一页”的向导，而是：

- 所有题目按 `order` 渲染在同一个页面，用户通过鼠标滚动浏览；
- 初始未作答时，所有题目按 `order` 显示；一旦某题作答命中跳转，路径外的题目默认隐藏；
- 用户作答触发跳转时，客户端重新计算路径，显示目标题及其后续可达题，隐藏离开路径的题，并平滑滚动到目标题；
- 用户修改前面的答案导致路径变化时，清除已经离开路径的题目的答案，避免提交无效数据；
- 页面底部固定一个“提交”按钮；提交前校验路径内全部必答题和格式，出错时滚动并聚焦到第一个错误题；
- 如果希望所有题目始终可见，也可以把“隐藏”改为“禁用/折叠”，但跳转计算和提交校验不变。本设计默认隐藏。

所有题目始终在同一个页面/DOM 中渲染，隐藏只是条件显示，不发生路由跳转或分页。扁平化只影响前端呈现，不影响服务端“计算路径、校验答案、只保存路径内答案”的模型。

### 3.7 其他已确认边界

- **全空白卷**：拒绝提交，空白提交不视为一次有效填写；一次提交至少包含一个有效答案（单选有选项、多选至少一项、文本去空白后非空、数字为合法数值）；MongoDB validator 的 `answers` 使用 `minItems: 1`。
- **创建者自填**：允许创建者填写自己的问卷，按普通答卷保存和统计，不做特殊排除。
- **文本长度**：按 Unicode 字符（code point）计数，emoji 算 1 个；前端和后端必须使用同一规则。
- **数字题**：以 `number` 存储；发布者设置 `min`、`max` 和数字类型。`integer=true` 为整数模式，只接受整数；`integer=false` 为小数模式，允许整数和小数。两种模式都必须落在 `[min, max]` 内。手机号、身份证号等不需要参与数值计算的编号建议用文本题，避免前导零丢失和精度问题。
- **截止时间**：数据库存 UTC；接口使用带时区的 ISO 8601；创建或修改问卷时截止时间必须晚于当前时间；`submittedAt <= deadline` 视为有效，超过即拒绝。
- **统计空值**：某题无人回答时 `answeredCount = 0`，数字题 `average = null`；百分比保留 2 位小数。
- **统计方式**：第一阶段实时聚合，不做缓存或物化统计。
- **关闭状态**：关闭后不可重新开放；需要重新收集时新建问卷或复制为新草稿（第二阶段可再扩展）。

## 4. 总体架构

```text
浏览器（单页填写界面，简单 HTML/JS 或任一前端框架）
        │ HTTPS + JSON
        ▼
后端 API
  ├─ Auth        注册、登录、JWT、权限
  ├─ Survey      问卷与题目管理、发布、关闭
  ├─ Response    答卷提交、重复限制
  ├─ Logic       校验引擎、跳转引擎（纯函数）
  └─ Stats       聚合统计
        │ MongoDB Driver
        ▼
MongoDB
  users / surveys / responses
```

后端建议分三层：

- Controller / Route：解析请求、鉴权、返回统一错误；
- Service：业务规则、事务边界、权限判断；
- Repository：MongoDB 查询与写入。

`Logic` 层不依赖数据库，输入是“问卷定义 + 答案”，输出是“题目路径 / 校验错误”，这样测试跳转和校验时不需要启动整个服务。

前端另有一个“填写引擎”（`fill-engine`），负责单页中的路径计算、题目显示/隐藏、滚动定位和失效答案清理。它只负责交互体验，最终结果以服务端重放校验为准。

## 5. MongoDB 设计

### 5.1 集合总览

| 集合 | 存什么 | 数据量 | 主要访问方式 |
|---|---|---|---|
| `users` | 账号、密码哈希、注册时间 | 小 | 按用户名登录 |
| `surveys` | 问卷元数据、题目、选项、跳转规则 | 中 | 按 `ownerId` 列表；按 `slug` 填写 |
| `responses` | 一次提交及其答案数组 | 大 | 按 `surveyId` 统计；按 `respondentId` / `dedupeKey` 查重 |

不把所有数据放进一个集合，原因是三者的生命周期、增长速度、权限和索引需求不同。尤其答卷会持续增长，不能内嵌到问卷文档里。

### 5.2 users

```javascript
{
  _id: ObjectId,
  username: "alice",
  passwordHash: "$argon2id$v=19$...",
  createdAt: ISODate("2026-10-18T10:00:00Z"),
  updatedAt: ISODate("2026-10-18T10:00:00Z")
}
```

约束：

- `username` 唯一，长度 3–32；
- 只存 `passwordHash`，使用 bcrypt / argon2id，禁止明文；
- 接口永远不返回 `passwordHash`。

```javascript
db.createCollection("users", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["_id", "username", "passwordHash", "createdAt"],
      properties: {
        _id: { bsonType: "objectId" },
        username: { bsonType: "string", minLength: 3, maxLength: 32 },
        passwordHash: { bsonType: "string" },
        createdAt: { bsonType: "date" },
        updatedAt: { bsonType: "date" }
      },
      additionalProperties: false
    }
  }
})

db.users.createIndex({ username: 1 }, { unique: true })
```

### 5.3 surveys

题目、选项和跳转规则内嵌在问卷文档中。示例：

```javascript

  ownerId: ObjectId("66f000000000000000000001"),

  description: "请根据实际情况填写",
  slug: "aB3xK9Qp",
  status: "published",

  allowMultipleResponses: false,
  deadline: ISODate("2026-12-31T15:59:59Z"),
  version: 1,
  createdAt: ISODate("2026-10-18T10:00:00Z"),
  updatedAt: ISODate("2026-10-18T10:05:00Z"),

  questions: [
    {
      _id: ObjectId("66f200000000000000000001"),

        { _id: ObjectId("66f210000000000000002"), order: 2, label: "女" },

        {

        { _id: ObjectId("66f220000000000000000002"), order: 2, label: "香蕉" },
        { _id: ObjectId("66f220000000000000000003"), order: 3, label: "西瓜" },
        { _id: ObjectId("66f220000000000000000004"), order: 4, label: "葡萄" }
      ],
      validation: { minSelections: 2, maxSelections: 3 },
      jumpRules: [
        {
          priority: 1,
          when: {
            operator: "setEq",
            value: [
              ObjectId("66f220000000000000000001"),
              ObjectId("66f220000000000000000004")
            ]
          },
          target: { type: "question", questionId: ObjectId("66f200000000000000000004") }
        }
      ]
    },
    {
      _id: ObjectId("66f200000000000000000003"),
      order: 3,
      type: "text",
      title: "其他建议",
      required: false,
      options: [],
      validation: { minLength: 0, maxLength: 500 },
      jumpRules: []
    },
    {
      _id: ObjectId("66f200000000000000000004"),
      order: 4,
      type: "number",
      title: "你的年龄",
      required: true,
      options: [],
      validation: { min: 0, max: 120, integer: true },
      jumpRules: [

```

字段说明：

| 字段 | 说明 |
|---|---|
| `ownerId` | 创建者，用于“只能看到自己的问卷” |
| `slug` | 发布后生成的短链接标识，全局唯一 |
| `status` | `draft` / `published` / `closed` |
| `allowAnonymous` | 是否不记录填写者身份 |
| `allowMultipleResponses` | 是否允许同一用户多次提交 |
| `deadline` | 截止时间，`null` 表示不限 |
| `version` | 问卷结构版本，为第二阶段预留 |
| `questions` | 有序的题目数组 |

题目通用字段：

| 字段 | 说明 |
|---|---|
| `_id` | 题目稳定 ID，答卷和跳转都引用它 |
| `order` | 展示顺序，从 1 开始 |
| `type` | `single` / `multiple` / `text` / `number` |
| `title` | 题干 |
| `required` | 是否必答 |
| `options` | 选择题的选项；非选择题为空数组 |
| `validation` | 题型相关的校验配置 |
| `jumpRules` | 该题作答后的跳转规则，按 `priority` 升序匹配 |

各题型的 `validation`：

| type | validation 字段 | 说明 |
|---|---|---|
| `single` | `{}` | 选项合法性由 `options` 保证 |
| `multiple` | `{ minSelections, maxSelections }` | “至少 2 个”= min=2, max=null；“最多 3 个”= min=0, max=3；“必须 2 个”= min=2, max=2 |
| `text` | `{ minLength, maxLength }` | 按字符数限制 |
| `number` | `{ min, max, integer }` | `integer=true` 只允许整数；`false` 允许整数和小数；两者都受 `min/max` 限制 |

`minSelections` / `maxSelections` 不额外设计 `exactSelections`，用 `min = max` 表达“必须选 N 个”，避免三套字段互相矛盾。

索引：

```javascript
db.surveys.createIndex(
  { slug: 1 },
  { unique: true, partialFilterExpression: { slug: { $type: "string" } } }
)
db.surveys.createIndex({ ownerId: 1, createdAt: -1 })
db.surveys.createIndex({ status: 1, deadline: 1 })
```

`slug` 只需在发布时生成；草稿阶段不写该字段。唯一索引必须使用 `partialFilterExpression` 或 `sparse`，否则多个“没有 slug”的草稿会被当成重复的 `null`。建议使用 8–10 位随机字符串（如 nanoid），不要用自增 ID，避免被枚举。

### 5.4 responses

一次提交存一条文档，答案内嵌为数组：

```javascript
{
  _id: ObjectId("66f300000000000000000001"),
  surveyId: ObjectId("66f100000000000000000001"),
  surveyVersion: 1,
  submissionId: "5c2f9d1e-7a4b-4f0e-9c3a-2b6d8e1f4a70",
  respondentId: ObjectId("66f000000000000000000002"),
  anonymous: false,
  dedupeKey: "66f100000000000000000001:66f000000000000000000002",
  answers: [
    {
      questionId: ObjectId("66f200000000000000000001"),
      type: "single",
      value: ObjectId("66f210000000000000000001")
    },
    {
      questionId: ObjectId("66f200000000000000000002"),
      type: "multiple",
      value: [
        ObjectId("66f220000000000000000001"),
        ObjectId("66f220000000000000000002")
      ]
    },
    {
      questionId: ObjectId("66f200000000000000000003"),
      type: "text",
      value: "课程节奏合适"
    },
    {
      questionId: ObjectId("66f200000000000000000004"),
      type: "number",
      value: 21
    }
  ],
  startedAt: ISODate("2026-10-18T10:10:00Z"),
  submittedAt: ISODate("2026-10-18T10:12:30Z"),
  durationMs: 150000
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `surveyId` | 所属问卷 |
| `surveyVersion` | 提交时的问卷结构版本 |
| `submissionId` | 前端为一次填写生成的 UUID，用于提交幂等 |
| `respondentId` | 登录用户 ID；匿名时为 `null` |
| `anonymous` | 是否匿名提交 |
| `dedupeKey` | 可选，用于唯一索引防重复；非匿名为 `surveyId:userId`，匿名为 HMAC 值；不适用时**不写该字段** |
| `answers` | 只保存实际访问并作答的题目 |
| `startedAt` / `submittedAt` | 用于计算填写耗时 |

答案的 `type` 是有意保留的少量冗余：统计时不必回查题目类型，且能防止问卷结构变化后答案语义不清。由于发布后冻结题目结构，这种冗余是可控的。

约束与索引：

```javascript
db.createCollection("responses", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: [
        "_id", "surveyId", "surveyVersion", "submissionId", "anonymous",
        "answers", "submittedAt"
      ],
      properties: {
        _id: { bsonType: "objectId" },
        surveyId: { bsonType: "objectId" },
        surveyVersion: { bsonType: "number" },
        submissionId: { bsonType: "string", minLength: 8, maxLength: 64 },
        respondentId: { bsonType: ["objectId", "null"] },
        anonymous: { bsonType: "bool" },
        dedupeKey: { bsonType: "string" },
        answers: {
          bsonType: "array",
          minItems: 1,
          items: {
            bsonType: "object",
            required: ["questionId", "type", "value"],
            properties: {
              questionId: { bsonType: "objectId" },
              type: { enum: ["single", "multiple", "text", "number"] },
              value: {
                bsonType: ["objectId", "string", "int", "long", "double", "array"]
              }
            },
            additionalProperties: false
          }
        },
        startedAt: { bsonType: "date" },
        submittedAt: { bsonType: "date" },
        durationMs: { bsonType: "number" }
      },
      additionalProperties: false
    }
  }
})

db.responses.createIndex({ surveyId: 1, submittedAt: -1 })
db.responses.createIndex({ surveyId: 1, respondentId: 1 })
db.responses.createIndex({ surveyId: 1, "answers.questionId": 1 })
db.responses.createIndex({ surveyId: 1, submissionId: 1 }, { unique: true })
db.responses.createIndex({ dedupeKey: 1 }, { unique: true, sparse: true })
```

注意：`dedupeKey` 不适用时不要写成 `null`，直接省略字段，避免稀疏唯一索引把多个 `null` 当成重复。

`{surveyId, submissionId}` 唯一索引用于提交幂等：同一个填写页的重复请求命中同一 `submissionId` 时，服务端返回已存在的 `responseId`；如果同一个 `submissionId` 对应的答案内容不同，返回 409 `SUBMISSION_CONFLICT`，不覆盖原答卷。

判断“答案内容是否相同”时要做规范化：按 `questionId` 排序，多选答案按 `optionId` 排序并去重，再序列化或计算哈希，不能依赖 JSON 字段顺序。

### 5.5 为什么这样设计

**为什么题目内嵌在 survey 中？**

- 题目总是和问卷一起读取，内嵌后一次查询即可拿到完整问卷；
- 一份问卷的题目数量有界，通常几十题，不会无限增长；
- 发布问卷时需要原子地校验和切换状态，内嵌更简单；
- 跳转规则引用题目 ID，内嵌能保证问卷结构的一致性。

如果未来要做“题目库复用”或单份问卷题目数量极大，再拆出 `questions` 集合。

**为什么答卷单独集合、答案内嵌？**

- 答卷数量会持续增长，内嵌进问卷会撞上 16 MB 文档上限；
- 多人同时提交时，写同一条问卷文档会产生写冲突；
- 一次提交是一条文档，插入天然原子，不需要跨文档事务；
- 答案数组的长度由题目数量决定，是有界的；
- 统计用 `$unwind` + `$group` 即可完成，不需要额外的关联表。

**为什么不用关系数据库结构？**

- 问卷的题目数量、题型、选项和跳转规则都是可变结构，关系模型需要大量表或多层关联；
- 问卷天然是一个聚合根，文档模型与“读取整份问卷、提交整份答卷”的访问模式一致；
- 第二阶段需求变化时，文档模型可以通过新增可选字段和规则类型扩展，迁移成本更低；
- MongoDB 的聚合管道适合做选项计数、平均值等统计。

**哪些地方用了冗余？**

- 答卷答案中保存 `type`；
- 问卷中保存 `ownerId`，而不是每次从用户反查；
- 不做选项文案快照，避免答案文档膨胀；通过“发布后冻结结构”保证选项 ID 与文案稳定。

### 5.6 一致性与并发

- 提交答卷是单文档 `insertOne`，原子完成；
- `{surveyId, submissionId}` 唯一索引是提交幂等的最终防线：重复请求返回已有答卷，避免双击或网络重试造成重复插入；
- 不允许重复提交时，唯一索引 `dedupeKey` 是第二道防线，捕获 `E11000` 后返回 409；
- 发布问卷用条件更新：`{_id, ownerId, status: "draft"}`，避免重复发布或越权；
- 截止时间在读取问卷和提交答卷时都检查，采用“懒关闭”：过期即拒绝，不依赖定时任务；
- 统计直接聚合已提交答卷，第一阶段不维护计数器，避免计数器与真实数据不一致。

### 5.7 安全与权限

- 密码只存 bcrypt / argon2id 哈希，接口不返回 `passwordHash`；
- 所有问卷管理接口同时校验登录状态和 `ownerId`，防止水平越权；
- 填写接口也必须登录，只返回问卷内容，不返回 `ownerId`、其他答卷或统计数据；
- 匿名答卷的创建者接口不返回 `respondentId` 和 `dedupeKey`，创建者只能看到答案内容；
- `submissionId` 只用于提交幂等，使用随机 UUID，不写入 URL 或日志，也不能当作身份凭证；
- 服务端对每个答案重新校验，不信任前端传入的题型、路径或选项合法性；
- 文本答案渲染到页面时必须做 HTML 转义，防止存储型 XSS；
- 登录和提交接口建议加基础限流；
- 如果使用 httpOnly Cookie 保存 token，需要考虑 CSRF（SameSite 或 CSRF token）；如果使用 `Authorization` 头，则注意前端 XSS 风险。

## 6. 跳转与校验引擎

### 6.1 跳转规则模型

每条规则由“条件 + 目标”组成：

```javascript
{
  priority: 1,
  when: { operator: "eq", value: ObjectId("...") },
  target: { type: "question", questionId: ObjectId("...") }
}
```

目标也可以是结束：

```javascript
{ type: "end" }
```

条件运算符：

| 题型 | operator | value | 含义 |
|---|---|---|---|
| single | `eq` | optionId | 选中该选项 |
| multiple | `setEq` | optionId[] | 选中集合与配置集合完全一致（顺序无关，多一个少一个都不匹配） |
| number | `eq` / `ne` | number | 等于 / 不等于 |
| number | `gt` / `gte` / `lt` / `lte` | number | 大于 / 大于等于 / 小于 / 小于等于 |
| number | `between` | [min, max] | 数值在闭区间内 |

多选 `setEq` 的判定方式：把用户答案和规则配置都转成集合，先比较元素个数，再逐项检查是否都存在。选项顺序不影响结果；用户答案中的重复选项按一次计算，保存前应去重。配置集合为空、包含不属于该题的选项，或集合大小超出题目的 `minSelections` / `maxSelections`，都应在发布校验时拒绝。

匹配顺序：按 `priority` 升序，第一条命中的规则生效；没有命中则按 `order` 进入下一题；已经是最后一题则结束。在扁平化填写页中，“进入下一题”不是翻页，而是决定下一道可见题目以及滚动目标。

### 6.2 执行算法

同一个算法有两种模式，避免“单页预览”和“最终提交”互相冲突：

- `preview`：单页渲染时使用。未作答的题不报错，按默认顺序继续；只有已作答的题才评估跳转规则；
- `submit`：提交时使用。必答题缺失、答案非法或路径异常都直接报错。

```text
buildPath(survey, answersByQuestionId, mode):
  path = []
  visited = set()
  current = 按 order 排序后的第一题

  while current != null:
    if current.id in visited:
      throw INVALID_JUMP_LOOP
    visited.add(current.id)
    path.add(current.id)

    answer = answersByQuestionId[current.id]
    if answer 不存在:
      if mode == "submit" and current.required:
        throw MISSING_REQUIRED_ANSWER
      next = 下一题（按 order）
      current = next
      continue

    validateAnswer(current, answer)   // 类型、选项、数量、长度、范围

    target = null
    for rule in current.jumpRules 按 priority 升序:
      if evaluate(rule.when, answer):
        target = rule.target
        break

    if target == null:
      current = 下一题（按 order）
    else if target.type == "end":
      current = null
    else:
      current = 按 questionId 查找目标题

  return path
```

几个约定：

- 必答题未作答：直接报错，不能继续到后续路径，也不能提交；
- 选答题未作答：不评估跳转规则，按默认顺序进入下一题；
- 跳转只在当前题已作答且校验通过后评估；
- 运行时的 `visited` 和最大步数防止配置错误导致死循环。

扁平化页面下，前端用 `preview` 模式计算“当前答案对应的路径”。每次答案变化就重新计算一次：

- 路径内的题目显示；
- 路径外的题目隐藏（或按 UI 选择改为禁用/折叠）；
- 如果本次作答命中了跳转规则，滚动到目标题；
- 如果修改前序答案导致路径缩短，清除离开路径的题目答案。

### 6.3 提交时的服务端重放

客户端拿到题目和规则后可以在本地用 `preview` 模式计算路径和可见题目，但**服务端不能信任客户端提交的路径**。提交时服务端必须用 `submit` 模式重放：

1. 按 `surveyId` 读取当前问卷；
2. 检查状态是 `published` 且未过截止时间；
3. 检查登录、匿名设置和重复提交限制；
4. 检查 `submissionId` 非空且格式合法；如果 `{surveyId, submissionId}` 已存在，答案内容相同则直接返回已有 `responseId`，内容不同则返回 409 `SUBMISSION_CONFLICT`；
5. 用提交的答案重新执行 `buildPath(survey, answers, "submit")`；
6. 拒绝重复的 `questionId`；
7. 只保留路径内题目的答案，路径外的多余答案忽略；
8. 过滤后如果没有任何有效答案，返回 422 `EMPTY_RESPONSE`；
9. 路径内必答题缺失、答案非法、跳转目标不存在时返回 422；
10. 全部通过后插入一条 response；如果插入时命中 `submissionId` 唯一冲突，回查并返回已有结果。

这样即使客户端被篡改，统计也不会被污染。

### 6.4 发布前的静态校验

发布问卷时至少检查：

- 题目数量 ≥ 1；
- `order` 唯一且连续；
- 选择题至少 2 个选项，选项 ID 唯一；
- 多选题 `minSelections <= maxSelections`；
- 多选 `setEq` 的 `value` 是非空、无重复的选项 ID 数组，全部属于该题，且元素个数落在 `[minSelections, maxSelections]` 内；
- 文本题 `minLength <= maxLength`；
- 数字题 `min <= max`；
- 跳转目标存在，且第一阶段要求目标在当前题之后；
- 同一题内 `priority` 不重复；
- 规则引用的选项属于当前题，运算符与题型匹配；
- 至少存在一条能到达结束的路径。

```json
      "answeredCount": 42,
      "average": 22.5,
      "min": 18,
      "max": 30
    }
  ]
}
```

注意：由于跳转会让部分题目被跳过，**单题的 `answeredCount` 可能小于 `totalResponses`**。百分比的分母应使用该题的 `answeredCount`，不能统一用总答卷数。

### 7.6 错误码

| HTTP | code | 场景 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数格式错误、字段缺失 |
| 401 | `AUTH_REQUIRED` | 未登录或 token 失效；所有业务接口（含填写）都要求登录 |
| 401 | `INVALID_CREDENTIALS` | 登录时用户名或密码错误 |
| 403 | `FORBIDDEN` | 访问他人问卷 |
| 404 | `NOT_FOUND` | 问卷、题目或答卷不存在 |
| 409 | `USERNAME_TAKEN` | 用户名已存在 |
| 409 | `DUPLICATE_RESPONSE` | 已提交过且不允许重复 |
| 409 | `SUBMISSION_CONFLICT` | 同一个 `submissionId` 对应了不同的答案内容 |
| 409 | `SURVEY_LOCKED` | 问卷已发布，题目结构不可再修改 |
| 409 | `DUPLICATE_KEY` | 未分类的唯一索引冲突 |
| 409 / 410 | `SURVEY_NOT_OPEN` | 未发布、已关闭或已截止 |
| 422 | `EMPTY_RESPONSE` | 过滤路径外答案后没有任何有效答案 |
| 422 | `ANSWER_INVALID` | 答案不符合题目校验 |
| 422 | `PUBLISH_INVALID` | 发布前校验不通过 |
| 422 | `JUMP_INVALID` | 跳转配置或提交路径非法 |
| 500 | `SLUG_GENERATION_FAILED` | 多次生成唯一 slug 失败 |

## 8. 统计实现要点

单选题计数：

```javascript
db.responses.aggregate([
  { $match: { surveyId: ObjectId("...") } },
  { $unwind: "$answers" },
  {
    $match: {
      "answers.questionId": ObjectId("..."),
      "answers.type": "single"
    }
  },
  { $group: { _id: "$answers.value", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
])
```

多选题计数需要多一次 `$unwind`：

```javascript
db.responses.aggregate([
  { $match: { surveyId: ObjectId("...") } },
  { $unwind: "$answers" },
  {
    $match: {
      "answers.questionId": ObjectId("..."),
      "answers.type": "multiple"
    }
  },
  { $unwind: "$answers.value" },
  { $group: { _id: "$answers.value", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
])
```

数字题统计：

```javascript
db.responses.aggregate([
  { $match: { surveyId: ObjectId("...") } },
  { $unwind: "$answers" },
  {
    $match: {
      "answers.questionId": ObjectId("..."),
      "answers.type": "number"
    }
  },
  {
    $group: {
      _id: null,
      count: { $sum: 1 },
      average: { $avg: "$answers.value" },
      min: { $min: "$answers.value" },
      max: { $max: "$answers.value" }
    }
  }
])
```

文本题直接投影 `answers.value` 并按 `submittedAt` 分页，避免一次返回过多内容。

统计返回约定：

- 某题无人回答时 `answeredCount = 0`；
- 数字题无人回答时 `count = 0`、`average = null`、`min = null`、`max = null`；
- 百分比统一保留 2 位小数；
- 多选题的百分比之和可能超过 100%，这是正常的，因为每个人可以选多个选项。

## 9. 测试设计建议

对应文档要求的六类测试，建议至少覆盖：

### 9.1 创建问卷

- 登录后创建草稿成功；
- 未登录创建返回 401；
- 用户 A 不能读取 / 修改用户 B 的问卷；
- 标题为空返回 400。

### 9.2 添加题目

- 添加单选、多选、文本、数字题成功；
- 选择题少于 2 个选项被拒绝；
- 多选题 `minSelections > maxSelections` 被拒绝；
- 文本题 `minLength > maxLength` 被拒绝；
- 数字题 `min > max` 被拒绝；
- 非草稿状态添加题目被拒绝。
- 发布后修改题目、选项、校验规则或跳转规则被拒绝。

### 9.3 跳转逻辑

- 单选选 A 滚动到第 5 题，第 3、4 题隐藏；
- 单选选 B 滚动到第 3 题；
- 多选精确匹配集合触发跳转；
- 多选顺序不同但集合相同仍触发（例如配置 `[苹果, 葡萄]`，提交 `[葡萄, 苹果]`）；
- 多选多一个选项、少一个选项都不触发；
- 多选未作答或空选时不评估跳转，按默认顺序显示下一题；
- 多选规则配置空集合、非法选项或超出 `minSelections` / `maxSelections` 时发布失败；
- 数字在区间内触发跳转；
- 没有规则命中时按顺序显示下一题；
- 跳转到 `end` 正确结束；
- 跳转目标不存在 / 指向自身 / 形成环时发布失败；
- 多条规则同时命中时按 `priority` 取第一条。

### 9.4 校验

- 必答题未答被拒绝；
- 单选提交不属于该题的选项被拒绝；
- 多选少于下限、多于上限被拒绝；
- 文本短于下限、长于上限被拒绝；
- 文本长度按 Unicode code point 计数，emoji 只算 1 个字符；
- 数字超出范围、非整数（要求整数时）被拒绝；小数模式下范围内的整数和小数都能通过；
- 过滤路径外答案后没有任何有效答案，返回 422 `EMPTY_RESPONSE`；
- 客户端提交路径外的题目答案被忽略或被拒绝（按实现约定）。

### 9.5 提交问卷

- 正常提交保存一条 response；
- 未发布、已关闭、已过期问卷拒绝提交；
- 未登录填写或提交返回 401，前端跳转登录后能回到原问卷；
- 非匿名 + 不允许重复时，第二次提交返回 409；
- 允许重复时可提交多次；
- 匿名提交仍要求登录，但不保存 `respondentId`；
- 匿名 + 不允许重复时，第二次提交仍返回 409（依靠 HMAC `dedupeKey`）；
- 同一个 `{surveyId, submissionId}` 重复提交返回同一个 `responseId`，只保存一条答卷；
- 同一个 `submissionId` 携带不同答案再次提交，返回 409 `SUBMISSION_CONFLICT`；
- 允许重复提交的问卷中，双击提交不会生成两条，重新进入填写页后可以正常再提交一次；
- 创建者可以填写自己的问卷，答卷正常保存并计入统计；
- 并发提交时唯一索引能阻止重复；
- 截止时间边界（刚好到期、已过期）行为正确。

### 9.6 统计

- 单选各选项计数与总回答数正确；
- 多选每个选项被选择次数正确；
- 文本题能查看所有填写内容；
- 数字题平均值、最小、最大正确；
- 被跳转跳过的题目 `answeredCount` 小于总答卷数；
- 百分比分母使用单题 `answeredCount`，百分比保留 2 位小数；
- 某题无人回答时 `answeredCount = 0`，数字题 `average = null`。

### 9.7 单页填写交互

- 所有题目在同一个页面按 `order` 渲染，页面可以鼠标滚动；
- 回答触发跳转后，目标题进入视口，路径外题目隐藏；
- 修改前序答案导致路径变化时，离开路径的题目的答案被清除；
- 提交时只提交当前路径内的答案，隐藏题目的残留数据不会进入答卷；
- 必答题或格式错误时，页面滚动并聚焦到第一个错误题；
- 在单页中来回修改答案不会造成题目重复显示或答案串题。

### 9.8 状态与时间边界

- `draft → published → closed` 正常流转；
- `closed` 状态不能重新开放，题目也不能再修改；
- 截止时间按 UTC 存储，接口传入带时区的时间后换算正确；
- `submittedAt` 恰好等于截止时间时允许提交，超过 1 秒后拒绝；
- 关闭或过期后，前端显示不可填写，后端也拒绝绕过前端的提交。

建议用一组固定测试数据（例如 3 个用户、2 份问卷、每种题型各 1 题、10 份答卷），同时写 API 自动测试和一份手工验收步骤，报告中附输入、输出和实际结果。

## 11. 为第二阶段预留的扩展点

- `surveys.version`：结构变更时递增，答卷记录 `surveyVersion`；
- 跳转规则使用 `operator + value` 的通用结构，新增运算符不需要改数据库；
- 题型通过 `type` 分派，新增题型只需增加校验器和统计器；
- 统计与答卷存储解耦，后续可加 `survey_stats` 物化集合或缓存；
- API 预留 `/api/v1` 前缀，便于不兼容变更；
- 题目内嵌但保留 `_id`，未来拆成独立集合时可以平滑迁移。

## 12. 已确认口径与剩余问题

已确认的设计口径：

1. 创建、编辑、发布、填写、提交、查看统计等所有业务操作都必须登录；匿名只是问卷发布者设置的“答卷不记录身份”选项，不是免登录。
2. 问卷发布后，题目、选项、题目校验规则和跳转规则一律不能修改；标题、说明、截止时间仍可修改。
3. 填写页是单页扁平布局，所有题目在同一页面渲染，通过滚动浏览；跳转通过显示/隐藏题目加滚动定位实现。
4. 多选跳转采用集合精确匹配（`setEq`），选项顺序无关，多一个或少一个都不触发。
5. 匿名的验收标准是“问卷创建者看不到填写者身份”，不要求数据库层面绝对不可关联；系统内部可保留 HMAC `dedupeKey` 用于防重复，但该字段不通过接口返回。
6. 全空白卷拒绝提交，一次提交至少包含一个有效答案。
7. 每次填写使用 `submissionId` 做幂等，重复点击或网络重试不会生成多条答卷。
8. 问卷关闭是终态，第一阶段不提供重新开放。
9. 发布后标题、说明、截止时间仍可修改，题目结构冻结。
10. 创建者可以填写自己的问卷，按普通答卷保存和统计。
11. 文本长度按 Unicode code point 计数，前后端规则一致。
12. 数字题用于数值统计；手机号、身份证号等编号建议使用文本题。
13. 截止时间存 UTC，接口使用带时区的 ISO 8601，`submittedAt <= deadline` 视为有效。
14. 第一阶段统计实时聚合；无人回答时 `answeredCount = 0`、数字题 `average = null`，百分比保留 2 位小数。
15. 第一阶段不允许跳回前面的题或形成循环，只允许跳到后面的题或结束。

剩余待确认问题：暂无。第二阶段需求发布后，再根据变更补充新的设计决策。
