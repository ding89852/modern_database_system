## 2. 测试方式与命令

### 2.1 逻辑与 API 自动化测试

```powershell
cd /survey-app
npm test
```

测试文件：

- `test/logic.test.js`：跳转、校验、发布前规则检查、答案规范化；
- `test/api.test.js`：注册、创建问卷、添加题目、发布、填写、提交、幂等、并发、统计、匿名。

### 2.2 浏览器冒烟测试

需先启动 MongoDB 和 API 服务：

```powershell
mongod --dbpath .data\db --port 27017
npm start
```

另开终端：

```powershell
npm run smoke
```

冒烟测试使用真实 Chrome 完成：

1. 注册并自动登录；
2. 检查最近登录用户名缓存和点击回填；
3. 创建问卷、添加单选和数字题；
4. 保存草稿；
5. 发布；
6. 打开填写页并提交；
7. 在“我填写的”中查看只读答案；
8. 在“我发布的”中查看统计和作答用户；
9. 关闭问卷并确认；
10. 打开已关闭问卷的只读页面。

### 3.2 主流程问卷

问卷标题：`课程反馈`。

| 顺序 | 题型 | 题干 | 配置 |
|---|---|---|---|
| 1 | 单选 | 你的性别 | 男、女，必答 |
| 2 | 多选 | 你喜欢的水果 | 苹果、香蕉、西瓜；至少 2 个、最多 3 个；精确选中“苹果 + 香蕉”跳到第 4 题 |
| 3 | 文本 | 其他建议 | 选填，0–50 个字符 |
| 4 | 数字 | 年龄 | 必答，0–120，必须是整数 |

主流程答案：

```json
[
  { "questionId": "<第1题>", "value": "<男>" },
  { "questionId": "<第2题>", "value": ["<香蕉>", "<苹果>"] },
  { "questionId": "<第4题>", "value": 20 }
]
```

多选答案故意使用“香蕉、苹果”的逆序，用于验证 `setEq` 与顺序无关。

## 5. 详细测试用例

### 5.1 创建问卷测试

#### TC-01 正常创建问卷草稿

- **前置条件**：用户 `alice` 已注册并登录。
- **步骤**：
  1. 调用 `POST /api/surveys`；
  2. 调用 `GET /api/surveys` 查看列表。
- **输入**：

```json
{
  "title": "课程反馈",
  "description": "测试问卷",
  "allowAnonymous": false,
  "allowMultipleResponses": false
}
```

- **预期输出**：创建接口返回 201；`status=draft`；`questions=[]`；列表包含该问卷。
- **实际结果**：通过（`api.test.js` → “完整 API 流程”）。

#### TC-02 未登录不能创建问卷

- **前置条件**：不携带 token。
- **步骤**：调用 `POST /api/surveys`。
- **输入**：`{ "title": "未登录问卷" }`。
- **预期输出**：401，`error.code=AUTH_REQUIRED`。
- **实际结果**：通过（`api.test.js` → “创建权限和题目结构校验”）。

#### TC-03 用户只能访问自己创建的问卷

- **前置条件**：`alice` 创建问卷；`bob` 已登录。
- **步骤**：
  1. `bob` 调用 `GET /api/surveys/{aliceSurveyId}`；
  2. `bob` 调用 `GET /api/surveys`。
- **输入**：`alice` 的问卷 ID。
- **预期输出**：详情接口返回 404；`bob` 的列表中不包含该问卷。
- **实际结果**：通过（`api.test.js` → “创建权限和题目结构校验”）。

#### TC-04 空标题不能创建问卷

- **前置条件**：用户 `judy` 已登录。
- **步骤**：调用 `POST /api/surveys`。
- **输入**：`{ "title": "" }`。
- **预期输出**：400，`VALIDATION_ERROR`。
- **实际结果**：通过（`api.test.js` → “创建参数和发布前校验”）。

#### TC-05 截止时间必须是未来时间

- **前置条件**：用户 `erin` 已登录。
- **步骤**：
  1. 提交 `deadline = 当前时间 - 1 小时`；
  2. 提交 `deadline = 当前时间 + 1 小时`。
- **预期输出**：第一次返回 400，详情为“截止时间必须晚于当前时间”；第二次返回 201。
- **实际结果**：通过（`api.test.js` → “截止时间必须晚于当前时间”）。

### 5.2 添加题目测试

#### TC-06 添加四种题型

- **前置条件**：存在 `alice` 的草稿问卷。
- **步骤**：依次调用 `POST /api/surveys/{id}/questions` 四次。
- **输入**：
  - 单选：`required=true`，两个选项；
  - 多选：`minSelections=2`、`maxSelections=3`，三个选项；
  - 文本：`minLength=0`、`maxLength=50`；
  - 数字：`min=0`、`max=120`、`integer=true`。
- **预期输出**：四次均返回 201；题目 `order` 为 1、2、3、4；选择题返回选项 ID。
- **实际结果**：通过（`api.test.js` → “完整 API 流程”）。

#### TC-07 选择题少于两个选项被拒绝

- **前置条件**：草稿问卷。
- **步骤**：添加单选题，只传一个选项。
- **输入**：`{ "type": "single", "title": "单选", "options": [{ "label": "A" }] }`。
- **预期输出**：400，提示选择题至少需要 2 个选项。
- **实际结果**：通过（`api.test.js` → “创建权限和题目结构校验”）。

#### TC-08 多选最少数量大于最多数量被拒绝

- **前置条件**：草稿问卷。
- **步骤**：添加多选题。
- **输入**：`minSelections=3`、`maxSelections=2`。
- **预期输出**：400，提示 `minSelections` 不能大于 `maxSelections`。
- **实际结果**：通过（`api.test.js` → “创建权限和题目结构校验”）。

#### TC-09 批量保存题目和 clientId 映射

- **前置条件**：用户 `dave` 创建草稿问卷。
- **步骤**：
  1. 调用 `PUT /api/surveys/{id}/questions`；
  2. 提交两道题，第一题引用第二题作为跳转目标；
  3. 检查返回的最终 ObjectId。
- **输入**：题目 `clientId=q-one`、`q-two`；选项 `clientId=opt-a`、`opt-b`。
- **预期输出**：200；两道题 `order=1,2`；跳转目标等于第二题的最终 `_id`；单选跳转值等于选项 B 的最终 `_id`。
- **实际结果**：通过（`api.test.js` → “批量保存题目”）。

#### TC-10 空问卷不能发布

- **前置条件**：用户 `judy` 创建空草稿。
- **步骤**：调用 `POST /api/surveys/{id}/publish`。
- **预期输出**：422，`error.code=PUBLISH_INVALID`。
- **实际结果**：通过（`api.test.js` → “创建参数和发布前校验”）。

#### TC-11 发布后不能修改题目

- **前置条件**：问卷已发布。
- **步骤**：调用 `PATCH /api/surveys/{id}/questions/{questionId}`。
- **输入**：`{ "title": "不能改" }`。
- **预期输出**：409，`error.code=SURVEY_LOCKED`。
- **实际结果**：通过（`api.test.js` → “完整 API 流程”）。

### 5.3 跳转逻辑测试

测试数据使用 `logic.test.js` 的固定问卷：第 1 题单选 A/B；第 2 题多选 X/Y/Z；第 3 题文本；第 4 题数字。

#### TC-12 单选 eq 跳转

- **前置条件**：第 1 题配置：选 B → 跳到第 3 题。
- **步骤**：提交第 1 题 B、第 4 题 20，执行 `buildPath(..., "submit")`。
- **预期输出**：路径为 `[q1, q3, q4]`，跳过第 2 题。
- **实际结果**：通过（`logic.test.js` → “单选 eq 跳转跳过中间题”）。

#### TC-13 多选 setEq 精确匹配且顺序无关

- **前置条件**：第 2 题配置：精确选中 `[X, Y]` → 跳到第 4 题。
- **步骤**：提交第 2 题 `[Y, X]`。
- **预期输出**：路径为 `[q1, q2, q4]`。
- **实际结果**：通过（`logic.test.js` → “多选 setEq 精确匹配，顺序无关”）。

#### TC-14 多选多一个或少一个不跳转

- **步骤**：提交第 2 题 `[X, Y, Z]`，再单独提交 `[X]`。
- **预期输出**：第一组按默认顺序进入第 3 题；第二组触发多选数量校验错误。
- **实际结果**：通过（`logic.test.js` → “多选多一个或少一个都不跳转”、“多选数量校验”）。

#### TC-15 没有规则命中时按顺序下一题

- **步骤**：第 2 题提交 `[X, Z]`（不等于 `[X, Y]`），并回答第 3、4 题。
- **预期输出**：路径为 `[q1, q2, q3, q4]`。
- **实际结果**：通过（“多选多一个或少一个都不跳转”用例）。

#### TC-16 跳转到结束

- **步骤**：把第 2 题规则改为 `setEq [X,Y] → end`，提交第 1 题 A、第 2 题 `[X,Y]`。
- **预期输出**：路径为 `[q1, q2]`，不再进入第 3、4 题。
- **实际结果**：通过（`logic.test.js` → “跳转到 end 立即结束”）。

#### TC-17 多条规则按 priority 取第一条

- **前置条件**：第 1 题两条规则同时匹配 B：priority 1 → 第 3 题，priority 2 → 第 4 题。
- **步骤**：提交第 1 题 B、第 4 题 20。
- **预期输出**：路径为 `[q1, q3, q4]`，采用 priority 1。
- **实际结果**：通过（`logic.test.js` → “多条规则按 priority 取第一条”）。

#### TC-18 发布时拒绝向后跳转

- **前置条件**：第 2 题跳转目标改为第 1 题。
- **步骤**：调用 `validateSurveyForPublish`。
- **预期输出**：抛出 `JUMP_INVALID`，提示只允许跳到后面的题目。
- **实际结果**：通过（`logic.test.js` → “发布校验拒绝向后跳转”）。

#### TC-19 发布时拒绝永远无法命中的 setEq

- **前置条件**：第 2 题 `minSelections=2`，跳转集合配置为 `[X]`。
- **步骤**：调用 `validateSurveyForPublish`。
- **预期输出**：抛出 `JUMP_INVALID`。
- **实际结果**：通过（`logic.test.js` → “发布校验拒绝永远无法命中的 setEq 集合”）。

#### TC-20 服务端提交时重放跳转路径

- **前置条件**：主流程问卷第 2 题配置 `setEq [苹果,香蕉] → 第 4 题`。
- **步骤**：
  1. 通过 API 提交第 1 题、第 2 题 `[香蕉, 苹果]`、第 4 题；
  2. 调用统计接口。
- **预期输出**：第 3 题 `answeredCount=0`，证明服务端跳过了第 3 题；提交成功。
- **实际结果**：通过（`api.test.js` → “完整 API 流程”）。

### 5.5 提交问卷测试

#### TC-30 正常提交

- **前置条件**：问卷已发布，用户已登录。
- **步骤**：调用 `POST /api/fill/surveys/{slug}/responses`。
- **输入**：`submissionId` + 主流程答案。
- **预期输出**：201，返回 `responseId` 和 `submittedAt`；MongoDB 新增一条 `responses` 文档。
- **实际结果**：通过（`api.test.js` → “完整 API 流程”）。

#### TC-31 submissionId 幂等

- **步骤**：使用同一个 `submissionId` 和相同答案（题目顺序、多选顺序可不同）再次提交。
- **预期输出**：200，返回同一个 `responseId`；数据库仍只有一条答卷。
- **实际结果**：通过（“完整 API 流程”）。

#### TC-32 同一 submissionId 不同答案

- **步骤**：复用 `submissionId`，但修改第 2 题选项集合。
- **预期输出**：409，`SUBMISSION_CONFLICT`。
- **实际结果**：通过（“完整 API 流程”）。

#### TC-33 同一用户重复提交限制

- **前置条件**：`allowMultipleResponses=false`。
- **步骤**：换一个新的 `submissionId`，再次提交。
- **预期输出**：409，`DUPLICATE_RESPONSE`。
- **实际结果**：通过（“完整 API 流程”）。

#### TC-34 匿名提交

- **前置条件**：`allowAnonymous=true`，用户已登录。
- **步骤**：提交答卷；创建者查看答卷列表。
- **预期输出**：提交成功；响应中 `respondentId=null`；创建者接口不返回 `respondentId` 和 `dedupeKey`。
- **实际结果**：通过（“完整 API 流程”）。

#### TC-35 关闭问卷后拒绝提交

- **步骤**：创建者关闭问卷；填写者再次提交。
- **预期输出**：410，`SURVEY_NOT_OPEN`。
- **实际结果**：通过（“完整 API 流程”）。

#### TC-36 并发提交只保存一份

- **前置条件**：同一用户、同一问卷、`allowMultipleResponses=false`。
